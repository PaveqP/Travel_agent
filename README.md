# О! рядом — Flinters (трек «О!дин запрос»)

AI-помощник собирает поездку по России из свободного описания: подбирает билеты,
отели и занятия, сравнивает до пяти совместимых планов, отвечает на вопросы и
обновляет выбранные части маршрута. Веб-приложение использует FastAPI и PostgreSQL;
оформление заказа и оплата выполняются только в режиме имитации.

В приложении всё готово для полноценной интеграции с Telegram.

- **Демо-видео:** ещё не опубликовано. Перед сдачей нужно добавить общедоступную
  ссылку на скринкаст и проверить её в режиме инкогнито.
- [Правила оформления репозитория](https://docs.ostrovok.tech/s/b9e6ec5e-5ad6-4091-9c85-a48eee9b21cc).

## Быстрый старт

Нужны Git, Docker Engine и Docker Compose v2 (либо Docker Desktop). Python, Node.js
и PostgreSQL на хосте для этого способа запуска устанавливать не нужно.

```bash
git clone https://github.com/ostrovok-hackathon-2026/flinters.git
cd flinters
```

**Для жюри:** в корне находится `secrets.env.age` с зашифрованной рабочей
конфигурацией. Установите [age](https://github.com/FiloSottile/age#installation)
и расшифруйте её закрытым ключом организаторов:

```bash
age --decrypt -i /path/to/organizers-age-key.txt -o .env secrets.env.age
```

Замените путь на расположение закрытого ключа организаторов. После расшифровки
перейдите к `docker compose up --build`; дополнительные ключи заполнять не нужно.
Существующий рабочий `.env` сохраните перед расшифровкой.

**Для самостоятельной настройки без закрытого ключа организаторов:**

```bash
cp .env.example .env
```

В новом `.env` заполните `MODEL`, `TOKEN`, `BASE_URL` для OpenAI-совместимого LLM API
и задайте `TRAVEL_POSTGRES_PASSWORD`. Ключи выдаёт ваш провайдер; в репозитории их
нет. Модель должна поддерживать tool calling и structured output. Используйте
адрес API провайдера, включая `/v1`, если он требуется провайдером.
Если `.env` уже существует, сохраните его значения и не заменяйте файл шаблоном.

```bash
docker compose up --build
```

Откройте **[http://localhost:8080](http://localhost:8080)**. Создайте аккаунт через
кнопку регистрации; подтверждение email не требуется. Документация API доступна
на [http://localhost:8080/docs](http://localhost:8080/docs).

Compose автоматически собирает React и backend, запускает PostgreSQL, создаёт
таблицы и дожидается готовности сервисов. В корне используется `docker-compose.yml`.
Backend и nginx слушают `8080`; наружу опубликован nginx на `127.0.0.1:8080:8080`.

```bash
docker compose ps
docker compose logs -f app
docker compose down
```

`down` сохраняет поездки в volume `travel_postgres`. Для повторного запуска после
правок используйте `docker compose up --build`. Не удаляйте volume для исправления
пароля: пароль существующей базы должен совпадать с первоначальным.
[Диагностика PostgreSQL и подробный запуск](docs/WEB_AND_TELEGRAM.md).

## Зависимости и ресурсы

Рекомендуемый ориентир для локального запуска: **4 CPU, 4 ГБ RAM и 5 ГБ свободного
диска** для Docker. GPU и загрузка весов моделей не нужны: LLM вызывается по API.
Первой сборке нужен доступ к Docker Hub, PyPI и npm; реальному поиску — к LLM и
API/MCP поставщиков. Время первой сборки зависит от сети и эмуляции архитектуры.

| Компонент | Назначение |
|---|---|
| Python 3.11, FastAPI, LangGraph, LangChain | Общий backend и оркестрация агентов |
| PostgreSQL 17 | Аккаунты, поездки, сообщения и checkpoints |
| React 19, Vite, Node.js 22 | Сборка веб-интерфейса; Node.js остаётся в стадии сборки |
| nginx 1.30.6 | Статика, проксирование API и SSE |
| OpenAI-совместимый LLM API | Supervisor, специалисты и ответы пользователю |
| Туту MCP, API карт/мест/погоды, Tavily | Данные транспорта, проживания и программы |

Redis, очередь сообщений и приватные пакеты/реестры для запуска не требуются.
Python-зависимости закреплены в `requirements.lock.txt`, frontend — в
`frontend/package-lock.json`. Базовые Docker-образы закреплены digest; оба
Dockerfile используют multi-stage build. Процессы backend, nginx и PostgreSQL
работают без root. В Compose явно указана `platform: linux/amd64`, в том числе
для сборки на Apple Silicon.

Рабочая конфигурация для жюри: провайдер **OpenRouter**, модель `deepseek/deepseek-v4.1-flash-1017`.

## Переменные окружения

Конфигурация передаётся backend через `env_file: .env`; frontend не получает
ключей. Открытый `.env` исключён из Git и Docker-контекстов. В Git хранится
только зашифрованный `secrets.env.age`, созданный по
[инструкции организаторов](https://docs.ostrovok.tech/s/b9e6ec5e-5ad6-4091-9c85-a48eee9b21cc/doc/shifrovanie-sekretov-klyuchej-6Qhc4gJOPZ).

| Переменная | Значение по умолчанию | Для чего нужна |
|---|---|---|
| `MODEL` | Нет, обязательна | Имя модели у вашего LLM-провайдера |
| `TOKEN` | Нет, обязательна | Серверный API-ключ LLM |
| `BASE_URL` | Нет, обязательна | Базовый URL OpenAI-совместимого API провайдера |
| `TRAVEL_POSTGRES_PASSWORD` | Нет, обязательна | Пароль новой PostgreSQL; для существующего volume — прежний пароль |
| `TRAVEL_POSTGRES_PORT` | `55432` | Порт PostgreSQL на хосте, доступен только через loopback |
| `TRAVEL_PUBLIC_URL` | `http://127.0.0.1:8080` | Публичный адрес приложения; для внешнего размещения задайте HTTPS URL |
| `TAVILY_API_KEY` | Пусто | Поиск и извлечение контекста; не источник подтверждённой цены |
| `YANDEX_RASP_API_KEY` | Пусто | Расписания транспорта |
| `TRAVELPAYOUTS_TOKEN` | Пусто | Дополнительные сохранённые транспортные предложения |
| `TWOGIS_API_KEY` | Пусто | Поиск мест через 2ГИС |
| `GEOAPIFY_API_KEY` | Пусто | Дополнительный поиск мест |
| `TIMEPAD_TOKEN` | Пусто | Поиск событий |
| `OPENTRIPMAP_API_KEY` | Пусто | Достопримечательности |
| `TRAVEL_API_TOKEN` | Пусто | Необязательный Bearer-доступ для CLI/интеграций; веб использует аккаунты |
| `TRAVEL_DATABASE_URL` | Пусто | Для запуска backend с хоста; в Compose адрес БД собирается автоматически |

В Compose адрес PostgreSQL — `postgres:5432`, пользователь и база — `travel`;
`TRAVEL_POSTGRES_HOST=postgres` задаётся самим Compose. Туту MCP и используемые
публичные Open-Meteo endpoints отдельного ключа не требуют. Отсутствие ключа
дополнительного источника или его сбой может дать частичный результат; сервис
не заменяет неизвестные данные выдуманными ценами.

В [`.env.example`](.env.example) все значения пустые. Значения по умолчанию
из таблицы выше задаются приложением и Compose. В шаблоне также перечислены
существующие исследовательские настройки `TRAVELPAYOUTS_MARKER`, `LITEAPI_API_KEY`,
`ORS_API_KEY` и совместимое имя `TAVILY`; исследовательские адаптеры для запуска
не нужны. `TAVILY` используется как ключ Tavily при пустом `TAVILY_API_KEY`.
[Подключение источников](docs/API_KEYS_SETUP.md) и
[аудит интеграций](docs/INTEGRATION_AUDIT.md).

## Данные и демо-сценарий

Сидирование вручную не требуется. При старте создаются таблицы аккаунтов,
сессий, поездок, checkpoints и store. Предустановленных
пользователей, паролей и готовых бронирований нет: зарегистрируйте собственный
аккаунт в интерфейсе. Ключи провайдеров и LLM нужны для реального подбора.

Пример запроса после регистрации:

> Из Москвы в Сочи вдвоём на 5 ночей в следующем месяце. Хотим море, прогулки
> и два дня в горах. На билеты и проживание — до 120 тысяч рублей на всех.

1. Уточните пожелания в диалоге и дождитесь результатов источников.
2. Сравните полные планы либо попросите отдельно найти отели или билеты.
3. Откройте подробности отеля и транспорта; задайте вопрос агенту или измените
   часть поездки, например: «Отель подешевле, билеты оставь прежними».
4. Выберите вариант, скачайте PDF и при желании подтвердите **имитацию** оформления.
5. Откройте сопровождение: программа по дням, отметки и помощь в поездке.

Направления — города, посёлки и курорты России, без фиксированного allowlist;
каталог на главной служит примерами. Поиск занимает время и может завершиться
частичным результатом, если поставщик не ответил или данных недостаточно.

Для offline-проверок есть fixtures в `tests/fixtures/`: тесты используют mock
LLM/HTTP/MCP. Они не загружаются в пользовательскую БД и не выдаются за живые
предложения. Исторические ответы источников сохранены в `reports/` для аудита;
их цены не являются актуальными котировками.

## UI, API и доступ

Все публичные HTTP-маршруты находятся на `http://localhost:8080`:

| Маршрут | Назначение |
|---|---|
| `/` | React: регистрация, диалог, варианты поездки и сопровождение |
| `GET /health` | HTTP 200 и JSON `{"status":"ok","persistent":true}` после запуска с PostgreSQL |
| `/docs`, `/openapi.json` | Swagger и OpenAPI-контракт |
| `POST /api/auth/register`, `POST /api/auth/login` | Регистрация и вход по email/паролю |
| `GET /api/account` | Профиль текущего пользователя |
| `GET /api/config` | Публичная конфигурация приложения |
| `GET /trips`, `POST /trips` | История и создание поездки |
| `GET /trips/{id}`, `DELETE /trips/{id}` | Чтение и удаление своей поездки |
| `POST /trips/{id}/messages` | Диалог и изменение ограничений, тело `{message, revision}` |
| `GET /trips/{id}/status`, `GET /trips/{id}/events` | Прогресс поиска и SSE |
| `POST /trips/{id}/select/{option_id}` | Выбор актуального предложения с проверкой revision |
| `POST /trips/{id}/bookings` | Оформление только имитационного заказа с явным подтверждением |
| `GET /trips/{id}/itinerary.pdf` | Маршрутный PDF, до оформления — черновик |
| `GET /trips/{id}/progress`, `PUT /trips/{id}/progress` | Отметки подготовки и посещённых мест |

Веб использует cookie-сессию; чужие поездки недоступны. Тестовой учётной записи
`admin/admin` нет.

## Архитектура и ограничения

Supervisor понимает запрос и делегирует задачи трём ограниченно автономным ReAct-
специалистам: Transport, Stay и Experience. Они получают только разрешённые
инструменты; независимые задачи выполняются параллельно. Python проверяет
происхождение данных, денежный basis, даты и совместимость компонентов. При
изменении ограничений повышается revision и обновляются зависимые данные.

- Деньги не списываются, реальные места не резервируются. В заказе:
  `simulated=true`, `paid=false`, `reserved=false`.
- Известная сумма обычно покрывает билеты и проживание. Питание, трансферы,
  активности и сборы могут оставаться неизвестными; неизвестное не равно нулю.
- Поисковое предложение и сохранённая цена не подтверждают наличие или бронь.
- Автоматического мониторинга рейсов и отправки писем поставщикам нет.
- MVP рассчитан на взрослых и одну базу проживания; сложные поездки с несколькими
  отелями и полноценная работа с детскими тарифами не заявлены.

Код runtime — в `travel_agent/`, адаптеры — в `integrations/`, React — в
`frontend/`, проверки — в `tests/`. `scripts/` и исследовательские сценарии не
импортируются в серверный путь.

## Проверки

Для разработки без Docker нужен Python 3.11+ и Node.js 22. Проверки по умолчанию
не вызывают платные LLM или внешние API:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python -m unittest discover -s tests -v
cd frontend
npm ci
npm test
npm run build
```

Проверка запущенных контейнеров:

```bash
docker compose ps
curl --fail http://localhost:8080/health
```

PostgreSQL, backend и frontend имеют healthcheck и зависимости готовности.
Приложение пишет диагностику в stdout/stderr: `docker compose logs app`.
[Локальный CLI и API](docs/TRAVEL_AGENT.md),
[автономное планирование](docs/AUTONOMOUS_PLANNING.md),
[веб-интерфейс](docs/WEB_AND_TELEGRAM.md),
[расширение географии](docs/RUSSIA_IMPLEMENTATION.md).

[Навигация по документации](docs/README.md) отделяет актуальные инструкции
от исторических исследований. [Проверка требований к сдаче](docs/SUBMISSION.md)
содержит результаты проверки запуска и оставшиеся действия.

## Перед сдачей

- Добавить публичную ссылку на демо-видео в начало этого README и проверить
  просмотр без авторизации.
- В дедлайн поставить тег `submission` на финальном коммите `main` и отправить
  его в основной репозиторий команды. Пока финальная версия не выбрана, тег
  намеренно отсутствует.
- Проверить чистый запуск по инструкции выше с действующими LLM-ключами.
  Скрипты `run_all.py` и live smoke не нужны для развёртывания и могут расходовать
  квоты; платные проверки запускаются отдельно с явным бюджетом.
