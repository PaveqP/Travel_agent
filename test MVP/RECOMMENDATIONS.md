Ниже подтверждённые наблюдения; гипотезы о причинах названы отдельно. Новые агенты, MCP и инфраструктурные сервисы не нужны. Код продукта и промпты в ходе измерения не исправлялись.

## По компонентам

- **Supervisor:** умеет планировать/делегировать и отвечать без повторного поиска (case_01 ход 2, case_02 ход 3), но extraction теряет факты case_03. Программа запрашивается даже в кейсах, где основная цель — объяснение/сравнение; это увеличивает latency.
- **ReAct:** стандартные bounded циклы реально выполнялись; caps срабатывают. Часты agent_limit/finalization_failed. В логах есть output_tokens=4096 с последующим ValidationError; обрезка — гипотеза, finish_reason не сохранён. Нет оснований просто повышать все лимиты.
- **StateGraph:** независимые специалисты уже идут параллельно, зависимости применяются. Один repair действительно ограничен одним кругом. Перенос дат меняет revision и создаёт свежие совместимые options, однако deadline может завершить HTTP раньше финального ответа.
- **Travel Engine:** проверенные суммы transport+stay, RUB, party/room_stay и состыковки проверены по публичным options. Ошибки свободного текста presenter находятся вне этих расчётов. Защита mountain_days успешно запретила оформление неполного плана; обходить её нельзя.
- **Память:** restart и ownership проверены успешно. Case_04 сохраняет состав, бюджет и интересы при смене дат. Персонализация между независимыми сессиями и Telegram не измерены.
- **MCP/API:** Tutu/2ГИС и несколько REST реально отвечали. Яндекс Расписания не вызывался. Нельзя требовать все доступные tools в каждом кейсе. Tavily не использовался как live price quote.
- **UI/backend:** fallback на HTTP обусловлен npm, а не доказанной ошибкой интерфейса. HTTP 200 со status=error в case_05 — общее сообщение приложения при отказе тестового budget guard; это не измерение качества самой пересборки бюджета.

Полный live-прогон пяти сценариев не завершён: case_05 не получил ни одного LLM/MCP вызова и не дошёл до уменьшения бюджета. Повторять его в рамках уже исчерпанного консервативного остатка нельзя. Самое полезное следующее измерение — отдельно начать с case_05 при новом явно выделенном бюджете, после устранения повторных циклов и потери параметров.
