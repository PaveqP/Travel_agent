# Автоматическая сборка тура: 29 октября 2026

Проверены две последние поездки в локальном PostgreSQL, checkpoints и журнал
backend. Истории, идентификаторы пользователей и ответы поставщиков в репозиторий
не добавлены. Платные LLM/MCP/API-проверки не запускались.

## Подтверждённые причины

- Для поездки Санкт-Петербург — Сочи, 10–20 ноября, трое взрослых, все обязательные
  вводные были сохранены. Поезд прибывал 12 ноября, а отели были проверены с 10-го.
  Stay запускался одновременно с Transport; исправление начинало новый поиск
  транспорта и программы. Общий deadline завершил ход прежде, чем были получены
  совместимые котировки проживания. Требование авиабагажа дополнительно
  применялось к железнодорожной альтернативе.
- Для поездки Санкт-Петербург — Шерегеш, 15–25 января, двое взрослых, обязательные
  вводные также были известны. Сохранены отели и места, но нет live-котировки
  транспорта; есть ошибки Tutu и незавершённая программа. Повторная просьба собрать
  тур снова закончилась частичным ответом. Причина отказа MCP раньше терялась:
  специалист видел только `schema_error`, без подсказки для исправления запроса.
- Общий лимит 120 секунд не покрывал планирование, два последовательных поиска
  Transport → Stay и один круг исправления. При остановке API показывал прежние
  `options`, не выполняя сборку по только что завершённым работникам.

Повторная проверка сохранённых котировок в памяти на момент исходных ответов
подтвердила: обязательные пользовательские поля заполнены в обеих поездках.
Для Сочи остаётся `arrival_stay_mismatch`, для Шерегеша — `no_transport` и
`no_day_plan`. Старую цену отеля нельзя перенести на другой интервал, а справочную
страницу авиакомпании нельзя превратить в проверенный билет.

## Исправления

- При достаточных обязательных параметрах граф продолжает сборку вместо вопроса
  о необязательных предпочтениях. Ответ с `focus=trip` без готового тура также
  направляется на сборку. Если Supervisor выбрал справочный ответ при несобранной
  поездке, он один раз перепроверяет намерение по последнему сообщению; настоящие
  справочные вопросы сохраняют свой маршрут.
- В полной поездке Stay ждёт результат нового поиска транспорта и получает местные
  даты прибытия и обратного отправления. При восстановлении транспорта в круге
  исправления несовместимый отель и программа, попавшая на дни дороги,
  перепроверяются в этом же круге. Совместимые
  компоненты сохраняются; посторонние задачи из RepairPlan не выполняются.
- Выбор карточки отеля в полной поездке продолжает сборку. Самостоятельный поиск
  отелей сохраняет свою область и не запускает транспорт или программу.
- Общий deadline составляет 300 секунд: он покрывает ограниченные последовательные
  этапы и один круг исправления. Лимиты каждого специалиста, tools и повторов не
  увеличены. До достижения deadline работа заканчивается сразу после готового
  результата. При остановке API собирает доступные пакеты из завершённых результатов
  и сохраняет их со статусом `partial`.
- Авиа запрашивается с `view=full`, поскольку нормализатор проверяет полный маршрут
  и тарифные условия. На этот запрос отведено до 32 секунд вместо 15, в пределах
  существующего бюджета специалиста. Отказы MCP передаются специалисту как
  ограниченный недоверенный текст причины; в журнал пишется только статус.
- Требование зарегистрированного авиабагажа не блокирует ЖД. Промпт разделяет даты
  поездки и проживания, сохраняет прямой рейс при сравнении с поездом и не требует
  повторять уже известные сведения после ошибки источника.

## Проверки

В `tests/test_tour_completion.py` добавлены одиннадцать offline-регрессий: полные вводные
без бюджета и лишних вопросов, уточнение отсутствующего города с последующей
сборкой, позднее прибытие поезда, восстановление транспорта с перепроверкой отеля
и переносом программы с дней дороги,
выбор отеля, ошибочный ответ вместо сборки, перепроверка намерения Supervisor,
сборка завершённых работников при timeout, передача причины MCP-отказа и ЖД при
требовании авиабагажа. Проверяются состав пакета, календарь, суммы и реальные
вызовы mock-источников, а не только статус.

Полный `.venv/bin/python -m unittest discover -s tests -v`: 271 тест без ошибок,
12 пропущены по условиям окружения. Проверка diff и ссылок Markdown успешна.

Проверки не подтверждают текущие цены и наличие у реальных поставщиков. При
неустранимом отказе источника приложение сохраняет частичный результат; неизвестные
цены и наличие не выдаются за готовый тур или бронирование. Пользовательские
поездки при диагностике не изменялись.
