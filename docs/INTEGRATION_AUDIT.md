# Аудит текущих интеграций — 28.10.2026

Проверена `main` после `bcc6b5c` до `94e828a`. Основные новые изменения: сценарии и последовательное согласование компонентов, гибкие даты, сохранение предпочтений и checkout, React-портал, аккаунты, Telegram, PDF и отдельные Docker-сервисы. Рабочая директория перед аудитом была чистой.

Текущий сценарий отличается от прежнего автоматического подбора: **сценарий → выбор билетов → выбор отеля → программа → корзина**. Пока пользователь не выбрал сценарий или компонент, следующий поиск не начинается. Все интерфейсы используют общий backend.

Машиночитаемые наблюдения, включая неуспешные прогоны: [current_integration_audit.json](../reports/current_integration_audit.json). `.env`, MODEL, TOKEN и BASE_URL не изменялись. Реальных бронирований, оплат и отправки Telegram-сообщений не было.

## Выявленные и исправленные причины сбоев

1. После диалога LLM получала ещё один HumanMessage с JSON-контекстом. «Последнее сообщение» могло означать этот JSON, и модель пропускала параметры. Контекст перенесён перед диалогом в Supervisor и presenter.
2. В сложном SupervisorDecision модель иногда формировала сценарии без полного TripDelta. Извлечение явно названных требований теперь выполняется отдельным `with_structured_output(TripDelta)` внутри Supervisor, с коротким [request.md](../travel_agent/prompts/request.md). Это не новая роль или framework. Для планирования добавляется ограниченный LLM-вызов; приветствия, вопросы и выбор карточкой его не требуют. Значения не достраиваются Python из догадок; невалидный контракт отвергается.
3. `transport_details` передавал только ID, хотя Tutu требует исходный компактный offer в `details_ref`. Теперь он берётся только из фактически наблюдённой выдачи текущей делегации. Проверка роли/продукта/владения сохранена.
4. Звёзды, рейтинг, число отзывов и описание расположения отеля терялись при нормализации. Теперь они доступны специалисту и карточкам. Это сведения Туту, а не собственная оценка качества.
5. Вопрос об отеле всегда зависел от отсутствующего Tavily. Stay research теперь сначала может запросить детали уже выбранного отеля через разрешённый Tutu Hotel. Они сохраняются как отдельный источник «Туту», не выдаются за выполненный веб-поиск. Произвольные чужие ID не разрешаются.
6. Внешний timeout поиска авиа 25 секунд отменял попытку раньше 30-секундного deadline MCP и не давал сработать безопасному повтору. Бюджеты согласованы: до 63 секунд на вызов, до 65 на ограниченный поиск; специалист по-прежнему ограничен 90 секундами. Ошибка первичного поиска сохраняется даже при fallback.
7. Один маршрут 2ГИС мог съедать минуту из бюджета Experience. Теперь ожидание ограничено 12 секундами, ошибка возвращается явно; каталог и другие данные сохраняются.
8. При незавершённом выборе Experience дни заполнялись произвольным каталогом. Теперь такие места остаются кандидатами, а незавершённость программы видна пользователю. Для выбранных мест движок чередует побережье/горы, сохраняя один район в пределах дня: районы побережья больше не вытесняют все горные дни.
9. Пустая выдача поездов/расписаний считалась успешным контекстом. Теперь возвращается `empty`; она не становится котировкой.
10. Compose требовал готового Telegram-бота даже при отсутствии его токена, блокируя frontend через `depends_on`. Healthcheck проверяет доступность web/API и постоянной БД; отключённый бот не блокирует веб. Его готовность отдельно видна в `/api/config`.

## Проверки и границы результата

Первый сквозной live-прогон не дошёл до поиска: потерялись исходные параметры. В последующих прогонах были как успешные сборки, так и пропуски дат и таймауты источников. Эти результаты не удалены из отчёта и не считаются успешной приёмкой. Финальный live-прогон с отдельным извлечением TripDelta прошёл все проверки: уточнение без поиска, полная сборка, сравнение стоимости без поиска, вопрос об отеле без изменения вариантов, замена на Mirror Residence без новых билетов и перенос на 13–17 ноября с обновлением трёх компонентов. Внешние ошибки и частичные результаты в некоторых попытках сохраняются в отчёте; это не доказательство постоянной доступности поставщиков.

Финальные offline-проверки: 124 теста, из них 119 прошли и 5 пропущены без PostgreSQL; с настоящим тестовым PostgreSQL прошли все 124 теста. Учтённые LLM-расходы и оставленный резерв за отменённый запрос — около $0.34, в пределах нового разрешённого бюджета $3. Точные суммы и итог полного PostgreSQL-набора записаны в JSON-отчёте.

На живой выдаче смешанного запроса получены билеты, отель, прибрежные и горные места, рестораны. После последнего изменения распределения дней отдельно воспроизведён **финальный детерминированный engine на этой сохранённой live-выдаче**: два горных дня, два прибрежных, рестораны «Белый гриб» и «Лихтенштейн», известная сумма 20 596 ₽ на двоих за билеты и проживание. Это снимок поисковых цен, не текущая гарантированная стоимость. Произвольные количественные пожелания по программе пока не являются строгой задачей оптимизации.

После pull локальной `.venv` не хватало уже объявленных `reportlab` и `pillow`; они установлены в версиях lock-файла. Portal/API, аккаунты, профиль, история, изоляция владельцев, восстановление после перезапуска, PDF, согласование, stale revision и mock booking проверены с отдельным настоящим PostgreSQL. Тестовая БД изолирована от пользовательских данных.

Четыре Node-теста прошли. `npm ci` с отдельным writable cache не завершился из-за таймаута registry.npmjs.org; production build и браузерный E2E в этом окружении не подтверждены. Telegram проверен offline и через общий PostgreSQL/API; живой Bot API не проверен — токен отсутствует. Сервис на localhost:8000 на момент начала аудита не работал.

## Повторить

Обновить локальные зависимости после pull:

```bash
uv pip sync --python .venv/bin/python requirements.lock.txt
```

Без сети и расходов:

```bash
.venv/bin/python -m unittest discover -s tests -v
node --test frontend/src/format.test.js
```

Для дополнительного PostgreSQL-режима задайте `TRAVEL_TEST_DATABASE_URL` **отдельной тестовой БД** и выполните тот же unittest.

Read-only источники, без LLM:

```bash
.venv/bin/python scripts/smoke_travel_sources.py --read-only --extended --output /tmp/travel-sources.json
```

Сквозной live-тест, расходует LLM/API-квоты; перед повтором согласуйте новый бюджет:

```bash
.venv/bin/python scripts/smoke_travel_agent.py --budget-usd 0.70 --dialogue --extended --output /tmp/travel-live.json
.venv/bin/python scripts/smoke_travel_agent.py --budget-usd 0.70 --mixed --output /tmp/travel-mixed.json
```

Для ручного диалога: `python chat.py --new`. После изменений кода перезапустите процесс; для Docker нужен rebuild приложения.
