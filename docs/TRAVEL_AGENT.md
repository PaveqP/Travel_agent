# Backend AI Travel Agent

FastAPI + CLI, а также [React и Telegram](WEB_AND_TELEGRAM.md) с общей PostgreSQL.
Supervisor формирует сценарии и понимает сообщения.
LangGraph управляет этапами и согласованиями. Transport, Stay и Experience
выполняют ограниченный ReAct по текущей задаче. Специалисты получают полные ответы поставщиков; подробности — [адаптивный агент](ADAPTIVE_AGENT.md). [План и результаты
реализации](SCENARIO_PIPELINE.md).

## Локальный запуск

Python 3.11+. Из корня репозитория, после заполнения `.env`:

```bash
uv venv
uv pip sync requirements.lock.txt
.venv/bin/python chat.py
```

При готовой `.venv` достаточно последней команды. `chat.py` выбирает интерпретатор
проекта и запускает FastAPI внутри процесса через ASGI. Отдельный сервер и Docker
не нужны. Используются прежние `MODEL`, `TOKEN`, `BASE_URL`; `.env` не изменяется.
Сетевой диалог использует квоты настроенных LLM/API.

Следующий запуск продолжает поездку. `.venv/bin/python chat.py --new` начинает
новую. SQLite `.travel-agent/checkpoints.sqlite` сохраняет этап, сценарии,
согласованные компоненты, программу, заказ и явно сохранённые предпочтения.
Директория исключена из Git. Не запускайте два локальных чата с одной поездкой.

## Пользовательский путь

1. Опишите поездку. Для размытого запроса Supervisor предлагает 1–4 разных
   сценария в Большом Сочи. Конкретный запрос может сразу перейти к поиску без выбора сценария. Цены и наличие сценария ещё не подтверждены.
2. Выберите сценарий через `/select НОМЕР` или словами. Агент уточняет только
   необходимые город отправления и число взрослых. Для предварительного поиска
   достаточно месяца или диапазона: точные даты согласуются выбором билетов.
3. Согласуйте перелёт. Только после выбора выполняется подбор проживания.
   Карточка показывает фактические даты и время; проживание автоматически
   подбирается от прилёта до обратного вылета, без отдельного подтверждения.
4. Выберите отель. Только после этого Experience строит программу около выбранного
   проживания. Предложения каталога не подтверждают часы работы или стоимость.
5. Согласуйте программу. Агент показывает общую корзину билетов и проживания,
   сумму за группу и на человека, неизвестные расходы и предупреждения.
6. `/book confirm` или явное подтверждение имитированной покупки оформляет
   локальный заказ. Проверяются этап, revision, свежесть, состав группы и совместимость дат. Превышение бюджета остаётся предупреждением.

Пример (актуальные даты заменяйте при необходимости):

```text
Хочу отдыхать у моря с друзьями в декабре, до 100000 рублей на человека.
/select 1
Из Санкт-Петербурга, четверо взрослых, вылет 10 декабря 2026, обратно 17 декабря.
/select 1
/select 1
Есть ли у выбранного отеля бассейн? Проверь в интернете.
/select 1
/show
/book confirm
/quit
```

`/select` всегда относится к последнему списку текущего этапа. После выбора
отеля следующий `/select 1` согласует показанную программу. Можно отвечать словами:
«выбираю второй перелёт», «берём этот отель», «программа подходит». Сам выбор
компонента не выполняет резерв или покупку. Вопрос о покупке не является согласием.

`/show` показывает сохранённое описание этапа. При вопросах оно сохраняется.
Команда `/profile море, прогулки` или просьба «запомни для следующих поездок…»
сохраняет явно названные интересы. Новая поездка получает их автоматически;
текущие ограничения от этого не меняются. Просьба забыть интересы очищает профиль.

## Изменения, ошибки и сопровождение

- Бюджет хранит основу `person`/`party`; общий предел рассчитывает Python.
  Названные месяц, календарные дни и ночи сохраняются отдельно. Противоречие
  длительности и точных дат останавливает поиск для уточнения.
- `start/end` относятся к транспорту, `check_in/check_out` — к проживанию.
  Смена дат транспорта снимает прежние переопределения проживания.
- Специалист сам выбирает запросы, даты и резервный источник по пожеланиям;
  скрытого перебора соседних дат и принудительного авиапоиска нет.
- Найденные предложения показываются с настоящими датами, ссылками и ценами,
  включая соседние даты, другой отель/район, превышение бюджета, старые котировки
  и кэш. Отклонения помечаются; выбор свежей карточки согласует её условия.
  Выбор старой или справочной карточки запускает проверку и показывает новую
  выдачу: её цена ещё не согласована. Перед покупкой ограничения проверяются.
- Изменение дат или гостей возвращает к транспорту; новый отель/район — к
  проживанию с сохранением совместимых свежих билетов. Изменение только программы
  сохраняет согласованные билеты и отель. Любое изменение требует нового
  согласования зависимых этапов. `patch.clear` явно снимает ограничения.
- Ошибка Supervisor сохраняет готовый план и выбор. Ошибки источника, пустая
  выдача и несовместимость различаются. Частичные котировки сохраняются; выдуманные
  варианты не добавляются. Истёкшая выдача обновляется автоматически, в том числе
  если ни один вариант не был выбран. Неудачное обновление не стирает старые
  карточки. Ошибка формата Supervisor получает одну попытку исправления.
- Вопросы об известных суммах не вызывают тарифный поиск. Веб-проверка отеля,
  района или транспорта использует сохранённые MCP-ответы, детали и при необходимости Tavily своей роли; для веба нужен `TAVILY_API_KEY`. Отсутствие ключа/данных сообщается явно.
- После покупки доступны заказ, маршрут и обсуждение деталей. Пересборка создаёт
  новую версию плана и не переписывает старый заказ. Автономного фонового слежения,
  рассылки напоминаний и реальных изменений у поставщиков нет.

Заказ содержит `simulated=true`, `paid=false`, `reserved=false`, состав, программу,
`missing_costs` и отдельный `payment.simulated=true`, `payment.status=succeeded`.
Это успешная **имитация** оплаты известных билетов и проживания. Питание, трансферы,
активности и дополнительные сборы не считаются оплаченными. Повтор с тем же
idempotency key возвращает прежний заказ; конфликт параметров отклоняется.

## Отдельный API

Для запуска сервера требуется `TRAVEL_API_TOKEN`. Без `TRAVEL_DATABASE_URL`
серверная память временная; локальный `chat.py` использует SQLite независимо
от этой настройки. Для PostgreSQL сохраните постоянные локальные значения:

```bash
export TRAVEL_POSTGRES_PASSWORD="$(.venv/bin/python -c 'import secrets; print(secrets.token_hex(24))')"
docker compose up -d postgres
export TRAVEL_DATABASE_URL="postgresql://travel:${TRAVEL_POSTGRES_PASSWORD}@127.0.0.1:55432/travel"
export TRAVEL_API_TOKEN="$(.venv/bin/python -c 'import secrets; print(secrets.token_hex(24))')"
.venv/bin/uvicorn travel_agent.api:app --host 127.0.0.1 --port 8000 --workers 1
```

Не генерируйте новый пароль для существующего PostgreSQL volume. В другом
терминале экспортируйте тот же `TRAVEL_API_TOKEN` и запустите
`.venv/bin/python -m travel_agent`. Сервер читает `.env`; удалённый CLI читает
API-токен из окружения процесса. Swagger: `http://127.0.0.1:8000/docs`.

Все операции поездки и профиля требуют `Authorization: Bearer TOKEN`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/trips` | Создать поездку |
| GET | `/trips/{trip_id}` | Состояние, этап, варианты, согласования и заказ |
| POST | `/trips/{trip_id}/messages` | `{message, revision}` — диалог |
| POST | `/trips/{trip_id}/select/{choice_id}?revision=N` | Выбор текущего этапа; возвращает обновлённое состояние |
| POST | `/trips/{trip_id}/bookings` | `{option_id, revision, confirm, idempotency_key}` |
| GET / PUT | `/profile` | Прочитать / сохранить JSON-массив интересов |
| GET | `/health` | Готовность и режим памяти |

`stage`: `scenarios`, `transport`, `stays`, `itinerary`, `review`, `booked`.
`choices` — текущий список для выбора; `options` — собранная корзина.
`cards` — структурированные предложения текущего этапа (до 30); 10 кандидатов
не сворачиваются в пустую выдачу из-за истечения цены или неподходящего фильтра.
В транспорте и проживании `choices` содержит те же карточки с дополнительным
`details`; в программе это кнопка согласования, а `cards` — найденные активности.
В корзине `cards` содержит выбранные билеты и отель.

Контракт `OfferCard`: `id`, `kind`, `title`, `description`, `aggregator`, `provider`,
`url`, `dates` (`start/end`, вылет, прилёт, обратный вылет), `price`,
`price_per_person`, `adults`, `evidence`, `freshness`, `retrieved_at`, `selectable`,
`action` и `warnings`. Деньги содержат `amount` как строку Decimal, `currency` и
`basis`; отсутствующая цена — `null`, без подстановки нуля. `dates` может содержать
`null`, если справочный источник даты не сообщил. `action=select` выбирает свежую
котировку, `verify` перепроверяет предложение через тот же `/select/{id}`,
`view` открывает справочную ссылку активности. `selectable=false` не скрывает
карточку. `notice` объясняет автоматическое обновление или принятые даты.

`selected_scenario`, `selected_transport`, `selected_stay` фиксируют согласования.
`receipt` содержит последний заказ, `bookings` — историю имитаций.
`diagnostics` содержит количества кандидатов и причины несовместимости.

`status`: `needs_input`, `needs_choice`, `ready`, `partial`, `booked`, `unsupported`,
`error`. `ready` означает готовность корзины к проверке, а не подтверждение оплаты
или полной стоимости. `409` — устаревшая revision, предложение, котировка либо
конфликт оформления; `504` — deadline (сначала прочитайте состояние); чужая
поездка возвращает `404`. Запуск — один worker, изменения поездки сериализуются.

## Источники и ограничения

| Роль | Источники |
|---|---|
| Supervisor | Нет внешних tools; структурированное решение |
| Transport | Tutu Transport, Яндекс Расписания, Travelpayouts, Tavily |
| Stay | Tutu Hotel, Tavily |
| Experience | 2GIS, Geoapify, Open-Meteo, Timepad, OpenTripMap, Tavily |

Полные ответы сохраняются в `results.<role>.observations`: `data`, исходный MCP
`response`, аргументы, источник и revision. Тарифы и карточки формирует агент;
Python проверяет ссылки на факты и арифметику, без фильтрации предложений по цене,
району или виду транспорта. Неизвестные поля и ошибки поставщика сохраняются.

Кэш, расписания и Tavily не заменяют наличие и тариф. Allowlist проверяется при
регистрации и перед сетью; details и seatmap принимают только принадлежащие
поездке IDs/references своего продукта. Реальные checkout, пассажирские документы
и платежи недоступны. ReAct использует `checkpointer=False`; внешний checkpoint
сохраняет полные observations, карточки и согласования.

У специалиста до восьми model calls, десяти tool calls и восьми сетевых операций,
deadline 90 секунд. У безопасного MCP-чтения до двух попыток только для временных
ошибок, общий deadline 63 секунды. Резервные источники и страницы выбирает модель.

Поддерживаются разные виды транспорта, классы и составы гостей в пределах
контрактов поставщика. Детские возраста и произвольные требования сохраняются.
Специальные услуги, скидки, наличие мест и условия номера подтверждаются только
данными источника. Их отсутствие не заменяется выдуманными фактами. Подробные
сценарии, ограничения и статус live-проверки — [в описании изменения](ADAPTIVE_AGENT.md).

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
uv pip check --python .venv/bin/python
```

PostgreSQL проверяется отдельно через `TRAVEL_TEST_DATABASE_URL`. Сетевой smoke
требует явного разрешения и бюджета. Исследовательский `scripts/run_all.py`
не нужен для проверки backend и меняет исторические отчёты.
[Актуальная проверка адаптивности](ADAPTIVE_AGENT.md),
[историческая live-проверка](TRAVEL_AGENT_VALIDATION.md).
