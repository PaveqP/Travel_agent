# Поездки по России

География схем и runtime расширена с Большого Сочи на произвольное название города, посёлка или курорта России. Каталог из 96 направлений на главной странице — набор примеров для вдохновения, не allowlist. Пользователь может указать другое направление свободным текстом.

Supervisor получил действие destinations: предлагает несколько разных городов с объяснениями и возвращает карточки выбора. Конкретное направление выбирает пользователь; лишь затем запускается полный поиск. Неизвестное направление больше не заменяется Сочи. Вводные из planner.patch и TripDelta объединяются; частичное извлечение не стирает остальные параметры.

Transport передаёт выбранный город в Tutu вместо AER/Сочи, поддерживает выбор ближайшего транспортного города для курорта, произвольные станции/города Яндекса и явный destination IATA для Travelpayouts. Смена города инвалидирует все три компонента и очищает старые результаты. Название транспортного узла сохраняется отдельно от курорта назначения. День прибытия и день заселения согласуются по фактическим локальным timestamps источника.

Experience разрешает названия через Open-Meteo Geocoding с countryCode=RU, получает координаты и timezone, ищет места по произвольным координатам/городу. Центр отеля имеет приоритет для nearby. Погода запрашивается с timezone=auto; Timepad получает выбранный город и локальные границы по найденной timezone. При неоднозначном названии инструмент возвращает варианты с admin1; агент может уточнить название регионом или передать точные координаты источника.

Удалены блокировки по сочинским прямоугольникам, обязательная привязка гор к Красной Поляне, фильтрация новых регионов на карте и автоматический Python-подбор активностей по районам. Календарь составляет Experience по своим наблюдённым source IDs. Горный день — метка mountain в программе, а не попадание в прямоугольник Поляны. Количественные пожелания остаются видимыми как предупреждения, не запрещают mock booking отдельной сочинской проверкой. Числовые фильтры отеля и соответствие пожеланиям оцениваются агентом/источником, а не скрывают выдачу в usable.

Сохранены изоляция владельцев и revision, allowlists инструментов, защита URL/секретов, валидация контрактов, корректный денежный basis и арифметика, свежесть котировок, согласованность транспорта/проживания и явное подтверждение симуляции. Реальная оплата/бронирование не выполняются. Каталог не означает подтверждённого покрытия каждого направления: доступность зависит от ответов поставщиков; отсутствующие сведения показываются явно.

Старые checkpoint с сочинскими названиями продолжают читаться: поле destination остаётся строкой, новые поля необязательны. Предыдущие тарифы не переносятся при выборе другого города. Для старых записей AER сохраняется совместимость с сочинским транспортом, без ограничения новых городов.

Запуск: `npm run build --prefix frontend`, затем `.venv/bin/python scripts/serve_web.py --local-postgres`. FastAPI раздаёт готовый React на http://127.0.0.1:8000. Локальная база и существующий .env используются без изменения ключей/модели.

По просьбе пользователя функциональные сценарии, live-поиски и автотесты в этой задаче не запускались. Выполнены компиляция Python, production build React, проверка diff и успешный старт сервисов. Старые отчёты об E2E описывают предыдущую версию; они не доказывают качество новой географии.

Для ручной проверки: «Предложи разные города России для пятидневного отдыха вдвоём из Москвы», выбрать направление; либо сразу «Из Москвы в Казань на 5 ночей, двое взрослых, до 80 тысяч на билеты и отель». Затем сменить город и проверить новые маршруты/даты. Можно ввести город, которого нет в каталоге. Это подсказки пользователю, не заявленный результат тестирования.
