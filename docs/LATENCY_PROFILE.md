Разбор 29 октября 2026. Источники: журнал backend и PostgreSQL checkpoint последнего полного поиска Владивостока. Идентификаторы пользователя и поездки, сырые ответы и история не публикуются. Платные запросы для диагностики не выполнялись.

Запрос выполнялся с 22:52:21 до 22:56:31 UTC: **250,3 секунды**. Вернулся частичный результат без законченной программы.

Stay ждал результатов транспорта, а повторный поиск календаря добавился после первого прохода. Перед этим уже существовали пригодные транспортные и гостиничные предложения.

Зарегистрировано 23 начала LLM-вызовов. Transport и Stay достигли лимита модельных шагов и выполняли дополнительные финализаторы: 17,5 и 17,1 секунды. Experience также не закончил календарь в ReAct, а повторный финализатор ждал 25 секунд и завершился timeout. Старый finally мог записать status=ok даже при отмене, поэтому эти записи не считаются доказательством успешного ответа поставщика.

Оценка 60–120 секунд до этого прогона не была подтверждена измерением и не соответствовала допускавшимся циклам. Старый общий timeout составлял 360 секунд, поэтому приложение действительно могло держать пользователя четыре минуты.

## Текущее изменение

- Общий лимит автономного выполнения — 120 секунд вместо 360. После истечения текущая работа отменяется, backend возвращает HTTP 200 со статусом partial и сохранёнными вариантами/карточками. Не запускается новый LLM для оформления ответа по timeout. История сохраняется, незавершённые задачи не возобновляются скрыто при следующем обращении. Это ограничение ожидания поиска, а не обещание полной программы за две минуты; отмена и сохранение требуют небольшого дополнительного времени.
- Автономный специалист ограничен 50 секундами. Поисковая часть оставляет до 15 секунд на существующий резервный финализатор.
- Четвёртый модельный шаг через стандартный wrap_model_call получает только structured-output tool. Внешние tools убираются из model request, поэтому последний шаг предназначен для результата, а не новой поисковой волны. Обычный путь больше не должен требовать пятого модельного шага ради завершения.
- Для автономных geocode_destination, weather, events и yandex_schedule предел чтения — 8 секунд. Остальные внешние операции ограничены 15 секундами. Полученное evidence не заменяется фиктивным результатом при timeout.
- Transport и Stay получают явное указание не генерировать календарь и возвращать days=[]. Справочные расписания не обязательны, если уже есть достаточные реальные котировки. Выбор инструментов остаётся у роли.
- Отменённые чтения логируются как cancelled. В финализаторе сохраняются безопасные пути полей ValidationError без ответов модели.
- UI показывает partial прежде, чем метку выбранного варианта, чтобы ограниченный результат не выглядел готовой поездкой.

## Проверки

218 Python-тестов без ошибок, 8 пропущены; 17 frontend-тестов прошли. Production build, compileall и diff check успешны.

Новые регрессии проверяют HTTP-ответ с найденными вариантами при зависшем Presenter, реальную отмену работы, восстановление результата после GET и отсутствие ожидающих узлов; состав tools на последнем модельном шаге; правильный исход журнала при отмене. Deadline в HTTP-тесте уменьшен до 0,5 секунды, внешние источники заменены offline mocks.

Полный живой запрос после этих изменений автоматически не повторялся. Реальную полноту результата и новое время необходимо измерять отдельно; уменьшение ожидания может увеличить долю явно обозначенных пробелов при медленных источниках.
