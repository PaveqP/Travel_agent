# Автономное планирование Большого Сочи

Источник текущего backend — [KilArtur/Flinters, коммит `f1dc3bf`](https://github.com/KilArtur/Flinters/commit/f1dc3bf). `travel_agent/`, `integrations/`, backend-тесты и скрипты перенесены целиком. Единственное отличие в Python-коде от этого снимка — кавычки внутри f-строки в `engine.py` для совместимости с Python 3.11; поведение и архитектура не изменены.

Новый режим включён по умолчанию в FastAPI, CLI, вебе и Telegram. Supervisor задаёт цели и зависимости. Специалисты самостоятельно выбирают инструменты, параметры и предложения. Travel Engine проверяет факты, деньги, географию и совместимость, возвращает адресные замечания. Граф допускает один круг исправлений с повторным использованием уже найденного evidence.

## Проверить как пользователь

Из корня репозитория с установленной `.venv` и существующим `.env`:

```bash
python chat.py --new
```

Дополнительно запускать сервер или PostgreSQL для этого локального диалога не нужно. Следующий `python chat.py` продолжит его из локального SQLite. Для проверки новой архитектуры начинайте с `--new`: старые пошаговые поездки автоматически не мигрируются.

Пример последовательности:

1. `Привет, кто ты?`
2. `Мы с девушкой хотим из Москвы в Сочи. На дорогу и проживание 100 тысяч на двоих. Хотим хороший отель, два дня в горах, остальное у моря, рестораны и прогулки.`
3. После вопроса о датах: `С 12 по 17 ноября 2026 года.`
4. `Сколько стоят билеты и проживание в первом варианте на человека? Ничего не меняй.`
5. `Есть ли бассейн у отеля из первого варианта? Проверь в интернете, поездку не меняй.`
6. `Замени отель на Mirror Residence, билеты оставь прежними.`
7. `Сдвинь поездку на 13–17 ноября 2026 года.`
8. `/select 1`, затем `/book confirm`.

Наличие конкретного отеля на новых датах не гарантировано. Если подходящий вариант уже найден, замена может выбрать его без повторного поиска. Неподтверждённые расходы и условия остаются неизвестными. Имитация покупки не выполняет оплату и не резервирует места.

В консоли показываются сообщения, этапы обработки и предварительно найденные названия; JSON не выводится. `/show` показывает план, `/quit` завершает диалог. Во время поиска запросы к поставщикам могут занимать десятки секунд.

## Устройство

```text
chat.py
travel_agent/
  api.py                   FastAPI, владельцы, прогресс, подтверждение покупки
  planning.py              автономный StateGraph и параллельные Send
  graph.py                 точка сборки, совместимость с пошаговым режимом
  schemas.py               TripConstraints, TripDelta, TurnPlan, результаты
  state.py                 TripState и reducer результатов параллельных задач
  engine.py                совместимость, бюджет, замечания, simulated booking
  agents/
    supervisor/            цели, маршрутизация, объяснение вариантов
    transport/             самостоятельный ReAct и транспортные tools
    stays/                 самостоятельный ReAct и инструменты отелей
    experience/            самостоятельный ReAct и программа по дням
    react.py               LangChain create_agent и стандартные middleware
    research.py            вопросы об отелях и районах без перепланирования
  prompts/                 Markdown-промпты и UTF-8 loader с кэшем
integrations/              существующие MCP и REST
```

Независимые задачи выполняются одновременно. Зависимости могут ссылаться как на новые задачи, так и на сохранённые результаты. Специалисты возвращают результаты через reducer; глобальный TripState обновляют узлы графа. Запоздалые результаты другой revision отклоняются.

Transport может сравнить авиа и ЖД. Для ЖД проверяются оба направления, хронология, состав группы и заявленный поставщиком денежный basis. Тариф за место умножается на взрослых один раз. Даты отеля согласуются с фактическим прибытием. Разные тарифы одного отеля на разные даты имеют разные ID, при обращении к MCP используется исходный ID поставщика.

Experience предлагает `days` со ссылками на найденные места. Engine проверяет ID, даты, районы, повторы и требуемое число горных дней. Он не сочиняет отсутствующую программу. Необязательная несовместимая транспортная альтернатива не задерживает уже совместимые пакеты.

Supervisor не получает внешних tools. Индивидуальные allowlists сохранены до регистрации и перед сетевым вызовом. Настройки `MODEL`, `TOKEN`, `BASE_URL` не изменены. Реальные checkout, пассажирские и платёжные методы запрещены.

## Скорость и продолжение диалога

Убраны обязательные пользовательские подтверждения каждого этапа и принудительный первичный поиск перед ReAct. Независимые специалисты работают параллельно. После двух шагов поиска модель получает только инструмент структурированного завершения через стандартный LangChain middleware. Сохраняются пределы четырёх model calls, шести ReAct tool calls и восьми вызовов адаптера.

Таймаут LLM — 20 секунд, внешнего чтения в автономном режиме — 20 секунд, специалиста — до 65 секунд, полного хода API — 180 секунд. `recursion_limit` остаётся дополнительной защитой. Исправление использует сохранённые факты, а не обязательно повторяет поиск. Повторяющиеся длинные ответы ассистента сокращаются при передаче в LLM, полная история остаётся в памяти. Отдельное извлечение TripDelta сохранено: текущий endpoint при большой комбинированной схеме иногда теряет явно сообщённые даты и цель.

API отдаёт прогресс через `GET /trips/{id}/status` и SSE `GET /trips/{id}/events`. Чтение поездки больше не ждёт блокировку длинного POST. CLI опрашивает прогресс раз в секунду; React подписывается на SSE. Это прогресс работы и найденные карточки, не поток внутренних рассуждений модели.

При вопросе результаты, выбранный вариант и revision сохраняются. Веб-исследование может использовать Tutu Hotel, Tavily Search и Extract. Флаг внутреннего исправления сбрасывается перед следующим пользовательским ходом. Изменение отеля сохраняет транспорт; изменение дат инвалидирует зависимые тарифы. Checkout требует явного подтверждения и поддерживает идемпотентность.

## API

При настроенных `TRAVEL_API_TOKEN` и PostgreSQL:

```bash
.venv/bin/uvicorn travel_agent.api:app --host 127.0.0.1 --port 8000 --workers 1
```

Для веба и Telegram используется существующий запуск из [WEB_AND_TELEGRAM.md](WEB_AND_TELEGRAM.md). PostgreSQL хранит серверные checkpoint, профили и аккаунты. Локальный SQLite нужен только существующему однокомандному CLI. `create_app(autonomous=False)` оставляет прежнюю пошаговую схему для совместимости.

## Проверки

Без сети и расходов:

```bash
.venv/bin/python -m unittest discover -s tests -v
node --test frontend/src/format.test.js
```

Отдельный PostgreSQL-режим — та же команда unittest с `TRAVEL_TEST_DATABASE_URL`, указывающим на тестовую БД. Проверяются восстановление нового графа после закрытия соединения, выбор поездки и прежние аккаунты/профили.

Live smoke выполняет только чтения и требует явного денежного лимита:

```bash
.venv/bin/python scripts/smoke_travel_agent.py --autonomous --mixed --extended --budget-usd 1 --output /tmp/travel-live.json
```

Он сохраняет реальные нормализованные результаты, длительности, делегирования, проверки и отдельный бюджетный файл. Повторный прогон зависит от доступности источников и может завершиться с частичным планом. Старые режимы исследовательских скриптов не доказывают работу нового графа.

Измеренные реальные сценарии и ограничения зафиксированы в [autonomous_validation.json](../reports/autonomous_validation.json). В успешном основном прогоне уточнение заняло 4,79 секунды, полный план с пятью вариантами — 59,10 секунды. В отдельном продолжении ответ о цене занял 7,51 секунды, исследование бассейна с Tutu и Tavily — 26,56 секунды. Эти измерения относятся к конкретным прогонам, не являются SLA.

## Ограничения

Внешние Tutu/2ГИС/Tavily периодически возвращают timeout или ошибку; повторные live-прогоны давали и частичные планы. После единственного круга исправлений недостающие данные показываются явно. Все live-сценарии не проходят стабильно при каждом повторе; это не доказанная production-надёжность.

Только Большой Сочи, взрослые, рубли, одна база проживания. Составные поездки с несколькими отелями, гарантированное наличие мест, полная стоимость ресторанов/трансферов/активностей, подтверждение снега и непредоставленные условия багажа не реализованы. До пяти проверенных вариантов — не глобальный рейтинг всех предложений.

React показывает прогресс SSE и предварительные находки, выбор готовых пакетов с программой и ценой на человека, отдельный подбор отелей и причины частичного результата. В автономном режиме изменения обсуждаются в чате без возврата к пошаговым подтверждениям. Оформление доступно после явного выбора пакета со свежими котировками. Подробное объяснение агента сохранено в раскрывающемся блоке.

При переносе прошли 158 backend-тестов (9 пропусков по условиям окружения), 11 JavaScript-тестов и production-сборка React. В браузере проверены настоящий API и новый граф с подставленными ответами специалистов: подбор, прогресс SSE, выбор пакета, имитация оформления, подбор только отеля и частичные результаты. Платные live-поиски при переносе не запускались; приведённые выше измерения относятся к исходному репозиторию.
