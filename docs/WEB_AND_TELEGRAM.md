# О! рядом: React и Telegram

Два интерфейса используют один FastAPI, существующий LangGraph и одну PostgreSQL.
Новые поездки не получают демонстрационные цены: карточки строятся из результатов
агентов. Поиск использует настроенные LLM и API; без ответа источника интерфейс
показывает уточнение, частичный результат или ошибку. География — Большой Сочи.

## Запуск

```bash
uv pip sync requirements.lock.txt
cd frontend
npm ci
npm run build
cd ..
.venv/bin/python scripts/serve_web.py --local-postgres --telegram
```

Последняя команда запускает существующий сервис `postgres` из `compose.yaml`,
ожидает готовности и запускает веб и бот в одном процессе. При первом запуске
создаёт случайный пароль PostgreSQL. При повторном использует пароль именно
контейнера `flinters-postgres-1`; существующий volume без контейнера требует
передать его прежний `TRAVEL_POSTGRES_PASSWORD`. Пароли не печатаются.
Без `--telegram` запускается только сайт. Сайт: [localhost:8000](http://127.0.0.1:8000).

Токен бота вводится скрыто и живёт только в окружении процесса. Не помещайте
его в React, Git, URL запуска или документацию. `.env` команда не изменяет.

Для уже развёрнутой PostgreSQL:

```bash
export TRAVEL_DATABASE_URL='postgresql://USER:PASSWORD@HOST:5432/DATABASE'
export TRAVEL_PUBLIC_URL='https://your-travel-domain.example'
.venv/bin/python scripts/serve_web.py --telegram
```

Можно передать `TELEGRAM_BOT_TOKEN` через окружение секретов и запустить без
флага `--telegram`. Сохраняются прежние `MODEL`, `TOKEN`, `BASE_URL` и ключи
провайдеров. Секреты LLM и Telegram не попадают в frontend. Веб-приложение
отказывается запускаться без PostgreSQL; fallback на SQLite отсутствует.

Разработка React: `cd frontend && npm run dev`. Vite проксирует API на порт
8000. После `npm run build` FastAPI раздаёт `frontend/dist`; отдельный Node-сервер
в рабочем режиме не нужен. Запуск — один worker. Для внешнего доступа необходимы
развёртывание FastAPI с PostgreSQL и HTTPS; команда локального запуска сама
по себе не публикует сайт в интернете. `TRAVEL_PUBLIC_URL` задаёт адрес кнопки
перехода из бота на сайт, по умолчанию это localhost.

## Пользовательский путь

1. Главная — описание поездки, примеры и карточки вдохновения. Перед отправкой
   первого запроса — регистрация, вход по email или вход через Telegram.
2. На компьютере чат остаётся слева, текущий шаг открывается справа. На телефоне
   доступны вкладки «Диалог» и «План поездки». При необходимости уточнений
   открывается диалог, при готовности вариантов — карточки.
3. Идея → билеты → отель → программа → проверка. Карточки содержат реальные
   поля ответа: даты, основу цены, источник, предупреждения и время перелёта,
   если оно известно. Фотографии на главной и сценариях иллюстрируют регион,
   фотографии конкретных отелей не подменяются изображениями других объектов.
4. Шаги сверху и «Назад» возвращают к предыдущему выбору без сетевого поиска.
   Повышается revision, сбрасываются зависимые согласования. Старые заказы
   остаются в истории. Обновить поиск или изменить ограничения можно в чате.
5. Проверка показывает билеты, проживание, известную общую сумму и программу.
   Форма оплаты содержит контактные поля, выбор карты/СБП и отдельное явное
   согласие на имитацию. Контактные поля этой формы используются только в UI;
   сайт не запрашивает настоящие реквизиты карты. Заказ создаёт прежний
   `simulate_purchase`: `simulated=true`, `paid=false`, `reserved=false`.
6. Итог поездки: детали каждого компонента, программа по дням, заказ, PDF и
   переход к сопровождению. PDF доступен и до оформления, с пометкой «Черновик».
   Неизвестные расходы не превращаются в нули и не входят в имитацию оплаты.
7. «В пути»: календарный статус поездки, подготовка, отметки посещённых мест,
   чат и справочник. Отметки сохраняются и видны в боте. Это сопровождение
   по сохранённому маршруту, без фонового мониторинга рейсов и push-напоминаний.

## Личный кабинет и память

Профиль создаётся при регистрации или первом обращении из личного чата Telegram.
Можно прочитать, изменить имя, телефон, город, интересы и удалить аккаунт вместе
с поездками, checkpoint, сессиями и связками. Email является идентификатором
входа. Город и интересы используются при создании следующего плана.

Пароли хэшируются scrypt с отдельной случайной солью. В БД хранятся только хэши
сессионных и одноразовых токенов. Сессия сайта — HttpOnly cookie с SameSite=Strict;
на HTTPS также Secure. Мутации cookie-сессии проверяют Origin и Sec-Fetch-Site.
Вход и регистрация ограничены по частоте. API-поездки проверяют владельца и
revision; чужие ID возвращают 404. Legacy Bearer API сохраняет совместимость.

PostgreSQL хранит таблицы `accounts`, `sessions`, `portal_trips`, `telegram_links`,
`web_login_links`, `telegram_state`, `bot_cursor`, а также существующие таблицы
LangGraph checkpoint и store. Таблицы создаются идемпотентно при старте.
Профиль, история сообщений, заказ, отметки, выборы и курсор бота переживают
перезапуск. База не хранит пароль банковской карты или токены внешних провайдеров.

## Telegram

Бот: [@ostrovok_helper_ryadom_bot](https://t.me/ostrovok_helper_ryadom_bot).
Работает через long polling Telegram Bot API, только в личных чатах. При старте
проверяет имя бота и регистрирует меню команд. Существующий webhook сохраняет:
если он настроен, polling останавливается с диагностикой вместо удаления чужой
конфигурации. После остановки серверного процесса бот перестаёт отвечать.

| Команда | Действие |
|---|---|
| `/start` | Приветствие и меню |
| `/new` | Новая поездка |
| `/trips` | Сохранённая история, открыть любую поездку |
| `/show` | Текущий шаг, описание и кнопки выбора |
| `/back` | Предыдущий этап с инвалидацией зависимых выборов |
| `/profile` | Профиль, изменение полей, отключение, удаление |
| `/pay` | Проверка корзины и отдельная кнопка имитации оплаты |
| `/pdf` | Тот же PDF файлом в чат |
| `/track` | Подготовка и отметки по маршруту |
| `/help` | Справочник и шаблоны писем |
| `/site` | Одноразовая ссылка входа на сайт с этим же аккаунтом |
| `/orders` | Сохранённые заказы с первоначальным составом и программой |
| `/cancel` | Отмена ввода поля профиля |

Обычные сообщения отправляются тому же графу, что и сообщения сайта. Inline-
кнопки содержат ID поездки, revision и индекс текущего выбора; устаревшие кнопки
не вызывают агентов. Оплата картой и СБП использует общий idempotency key для
веба и бота; смена способа при повторе того же ключа отклоняется.
Запросы разных интерфейсов к одной поездке сериализуются тем же API.

Если начали на сайте, в профиле выберите «Подключить Telegram» и нажмите Start
в боте по полученной ссылке. Она одноразовая и действует 10 минут. Если начали
в боте, используйте `/site`: ссылка войдёт на сайте в тот же аккаунт и сохранит
его историю. Одноразовый токен передаётся во фрагменте URL и удаляется из адреса
после входа. Разные аккаунты не объединяются автоматически; конфликт связки
сообщается явно. Отключение бота не удаляет веб-аккаунт.

## Сопровождение и письма

Общий справочник в `travel_agent/support.py`: задержка/отмена рейса, заселение,
багаж, обращение по качеству услуги. Сайт и бот показывают одинаковые инструкции
и шаблоны, подставляют только известные детали поездки. Неизвестные номера рейсов,
реальных бронирований и контакты оставляются полями для заполнения. Идентификатор
имитационного заказа не выдаётся за номер бронирования перевозчика или отеля.

Сообщения о письмах и типовых проблемах обрабатываются на основе этого же
справочника без платного вызова LLM и без изменения корзины. Остальной диалог
идёт существующему Supervisor. Подготовленные письма пользователь проверяет
и отправляет самостоятельно. Сервис не отправляет жалобы и письма поставщикам.

## Дополнительные API

| Метод | Путь | Контракт |
|---|---|---|
| POST | `/api/auth/register` | `{name, email, password}` |
| POST | `/api/auth/login` | `{email, password}` |
| POST | `/api/auth/telegram` | `{token}` одноразового входа |
| POST | `/api/auth/logout` | Отозвать текущую сессию |
| GET / PUT | `/api/account` | Профиль; PUT `{name, phone, city, interests}` |
| DELETE | `/api/account` | `{confirmation: "УДАЛИТЬ"}` |
| GET | `/trips` | История только текущего владельца |
| POST | `/trips/{id}/back` | `{stage, revision}` |
| GET | `/trips/{id}/itinerary.pdf` | PDF с кириллицей и деталями |
| GET / PUT | `/trips/{id}/progress` | PUT `{completed: {item_id: true}}` |
| GET | `/api/support` | Справочник и общие шаблоны |
| GET | `/trips/{id}/support/{guide_id}` | Шаблон с известными данными поездки |
| POST / DELETE | `/api/telegram/link` | Создать одноразовую связку / отключить |
| GET | `/api/config` | Публичный адрес и готовность бота |

Существующие API описаны в [TRAVEL_AGENT.md](TRAVEL_AGENT.md). GET поездки также
возвращает `messages`, `cards`, `notice`. Swagger доступен на `/docs`.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
cd frontend && npm test && npm run build
```

Offline-тесты используют mock LLM/HTTP; default-прогон не подключается к PostgreSQL
и внешним API. Для отдельной тестовой PostgreSQL передайте
`TRAVEL_TEST_DATABASE_URL` и запустите тот же unittest. Интеграционные тесты
создают отдельные аккаунты и проверяют настоящий PostgreSQL/checkpoint/store,
перезапуск, изоляцию, CRUD, CSRF, весь путь до оплаты, PDF, возврат, отметки,
Telegram-связку, одноразовый вход и устаревшие кнопки. LLM и Telegram замоканы.

Проверено при реализации: сборка, frontend-тесты, PostgreSQL-тесты, браузерный
путь на тестовой PostgreSQL, визуальный рендер PDF с кириллицей. Live-поиск
LLM/поставщиков не запускался ради проверки интерфейса.
