# О! рядом: веб и Telegram

React и Telegram используют один FastAPI, LangGraph и PostgreSQL. По умолчанию
Supervisor собирает поездку через трёх [автономных специалистов](AUTONOMOUS_PLANNING.md).
Результаты берутся у источников, без демонстрационных цен. География — Россия;
каталог направлений на главной служит примерами.

## Запуск

Основная инструкция — [README: быстрый старт](../README.md#быстрый-старт).
Нужны Git и Docker с Compose v2; Python, Node.js и PostgreSQL на хосте не нужны.
Для жюри готовый `.env` получается расшифровкой `secrets.env.age` закрытым ключом
организаторов; точная команда есть в README. После этого можно сразу запускать Compose.
При самостоятельной настройке в новом клоне скопируйте `.env.example` в `.env`, заполните `MODEL`, `TOKEN`,
`BASE_URL`, `TRAVEL_POSTGRES_PASSWORD`, затем выполните из корня:

```bash
docker compose up --build
```

Сайт: [http://localhost:8080](http://localhost:8080), Swagger — `/docs`.
Зарегистрируйте аккаунт, пароль — от 10 символов. Готового тестового аккаунта нет.
Таблицы создаются автоматически, ручные миграции и сидирование не требуются.

| Сервис | Назначение |
|---|---|
| `postgres` | PostgreSQL 17 и постоянный volume `travel_postgres` |
| `app` | Один процесс FastAPI, Supervisor, специалисты и polling Telegram |
| `frontend` | React, собранный через Vite, и nginx на порту `8080` |

`app` ждёт здоровую БД, `frontend` — здоровый `app`. Healthcheck приложения
проверяет HTTP и режим постоянного хранения. Образы backend и frontend собираются
в несколько стадий, все три процесса работают без root. Платформа — `linux/amd64`.
Конфигурация PostgreSQL внутри Compose задаётся автоматически; для доступа
с хоста используется `127.0.0.1:55432` (настраивается `TRAVEL_POSTGRES_PORT`).

Nginx проксирует API, Swagger и SSE на `app:8080`, сохраняет Host и query string.
HTML не кешируется, собранные `/assets/` кешируются по хешу. Секреты передаются
только backend; `.env`, отчёты и локальные зависимости не входят в образ.

```bash
docker compose ps
curl --fail http://localhost:8080/health
docker compose logs -f app
docker compose down
```

Ожидаемый ответ `/health`: `{"status":"ok","persistent":true}`.
`down` сохраняет данные. После правок используйте `docker compose up --build`.
Для внешнего размещения настройте HTTPS и `TRAVEL_PUBLIC_URL` с публичным адресом;
по умолчанию порты доступны только на loopback.
Запуск с хоста и React hot reload описаны в [TRAVEL_AGENT.md](TRAVEL_AGENT.md).

## Если запуск не удался

| Симптом | Действие |
|---|---|
| Compose просит переменную | Заполнить четыре обязательных поля корневого `.env` |
| Порт `8080` занят | Остановить прежний экземпляр приложения на этом порту |
| Порт `55432` занят | Задать свободный `TRAVEL_POSTGRES_PORT` |
| `password authentication failed`, затем `PoolTimeout` | Вернуть пароль существующей БД или синхронизировать его командой ниже |
| Ошибка загрузки образа/пакета | Проверить доступ Docker к Docker Hub, PyPI и npm, повторить сборку |
| Сайт открыт, поиск частичный или с ошибкой | Проверить LLM tool calling/structured output, ключи, доступность источников и логи `app` |
| Бот не отвечает | Проверить токен, готовность `/api/config`, логи и отсутствие второго polling/webhook |

`POSTGRES_PASSWORD` задаёт пароль только при первом создании БД; изменение `.env`
не меняет пароль существующего volume. `pg_isready` проверяет готовность сервера,
а не соответствие пароля приложения. Можно вернуть прежний пароль в `.env`.
Для синхронизации сохранённой БД с текущим паролем без удаления данных:

```bash
docker compose stop app
docker compose up -d --wait postgres
docker compose exec -T postgres sh -eu -c \
  'printf "%s\n%s\n" "$POSTGRES_PASSWORD" "$POSTGRES_PASSWORD" |
   psql -X -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "\password travel"'
docker compose up -d --wait
```

Пароль передаётся в скрытые приглашения `psql` и не печатается. Не используйте
`docker compose down -v` для исправления пароля: эта команда удаляет данные.

## Веб

1. Зарегистрируйтесь и опишите поездку свободным текстом. Можно искать полный
   план, только отели или только билеты. Для размытого запроса выберите направление.
2. Уточните недостающие параметры. Во время поиска видны этапы и предварительные
   находки; результат может быть частичным при сбое или отсутствии данных источника.
3. Сравните карточки, откройте детали билетов, отеля и программы. На компьютере
   детали справа, на телефоне — в отдельном окне. Цена показывает состав группы,
   даты и основу расчёта; фотографии отеля берутся из ответа поставщика.
4. Задайте вопрос или измените часть поездки: «Отель подешевле, билеты оставь».
   Вопрос сохраняет план, изменение обновляет зависимые компоненты.
5. Выберите готовый пакет, скачайте PDF и при желании подтвердите имитацию оплаты.
   Карта/СБП — имитация, настоящие реквизиты не нужны; деньги не списываются.
6. Используйте сопровождение: программа по дням, карта, отметки и чат по поездке.
   До оформления PDF помечен как черновик. Старый заказ хранит первоначальный состав.

Поездки и чаты сохраняются в аккаунте. Профиль позволяет изменить имя, город,
телефон и интересы, связать Telegram либо удалить аккаунт. Пароли хэшируются
scrypt; сессионные токены хранятся в виде хешей. Cookie — HttpOnly, SameSite=Strict,
на HTTPS — Secure. Мутации проверяют Origin; чужая поездка возвращает `404`.
Старая revision не может изменить новый план.

Истёкшие цены и справочные ссылки не выдаются за подтверждённое наличие.
Если Tutu возвращает только общую поисковую ссылку, интерфейс сообщает об этом;
ID предложения не превращается в выдуманную ссылку конкретного тарифа.

## Telegram

Бот: [@ostrovok_helper_ryadom_bot](https://t.me/ostrovok_helper_ryadom_bot).
Для собственного бота задайте `TELEGRAM_BOT_TOKEN` в серверном `.env` и пересоздайте
`app`. Без токена работает только сайт. Бот использует long polling и личные чаты;
существующий webhook не удаляет. Для одного токена нужен один процесс polling.
Фактическая готовность видна в `/api/config` как `telegram_configured` и в логах.

| Команда | Назначение |
|---|---|
| `/start`, `/new`, `/plan` | Главное меню, новая поездка, полный план |
| `/hotels`, `/tickets` | Отдельный поиск отелей или билетов |
| `/history`, `/show`, `/chat` | Поездки, текущий план, сохранённая переписка |
| `/profile` | Профиль и настройки аккаунта |
| `/pay`, `/orders` | Подтверждение имитации и сохранённые заказы |
| `/pdf`, `/map`, `/track` | PDF, карта, подготовка и отметки |
| `/help` | Справочник и шаблоны писем |
| `/site` | Одноразовая ссылка входа на сайт |
| `/cancel` | Отменить текущий ввод/подтверждение |

Обычный текст отправляется тому же агенту, что на сайте. Карточки показывают
сохранённые цены, источники и неизвестные условия; списки листаются кнопками без
нового LLM-поиска. Устаревшая кнопка не меняет текущий план. Имитация оплаты
требует отдельного подтверждения и привязана к выбранному варианту и revision.

Чтобы продолжать одну поездку в обоих интерфейсах, войдите на сайт, откройте
профиль и свяжите Telegram. Если начали в боте, `/site` выдаёт одноразовую ссылку
для того же аккаунта. Адрес в ссылке берётся из `TRAVEL_PUBLIC_URL`;
`localhost` с телефона указывает на сам телефон, для доступа к вашему ноутбуку
нужен доступный ему адрес сайта.

## API и сопровождение

Основные маршруты — в [README](../README.md#ui-api-и-доступ), полный контракт —
`/openapi.json`. Дополнительные:

| Метод | Путь | Назначение |
|---|---|---|
| GET / PUT / DELETE | `/api/account` | Профиль, изменение, удаление с `{confirmation: "УДАЛИТЬ"}` |
| POST | `/api/auth/logout` | Отозвать сессию |
| POST | `/api/auth/telegram` | Одноразовый вход `{token}` |
| POST / DELETE | `/api/telegram/link` | Связать / отключить Telegram |
| GET | `/trips/{id}/itinerary.pdf` | PDF с кириллицей |
| GET / PUT | `/trips/{id}/progress` | Отметки `{completed: {item_id: true}}` |
| GET / POST | `/trips/{id}/chats` | Чаты поездки; сообщения и удаление — по контракту OpenAPI |
| GET | `/api/support`, `/trips/{id}/support/{guide_id}` | Справочник и шаблон с данными поездки |

Сервис подставляет только известные данные. Пользователь проверяет и отправляет
письма сам; мониторинга рейсов, push-напоминаний и отправки писем поставщикам нет.
Имитационный ID не является номером реальной брони. Маркеры карты точные только
при координатах источника; район может быть отмечен приблизительно.

## Проверки и материалы

```bash
.venv/bin/python -m unittest discover -s tests -v
npm ci --prefix frontend
npm test --prefix frontend
npm run build --prefix frontend
npm run test:browser --prefix frontend
```

Браузерные регрессии используют Playwright с mock API. Если Chromium ещё
не установлен, выполните `cd frontend` и `npx playwright install chromium`.
Для обычного запуска приложения Playwright и локальный Node.js не нужны.
Отдельный режим PostgreSQL включается через `TRAVEL_TEST_DATABASE_URL` на тестовой БД.
Платные live-проверки запускаются отдельно с явным бюджетом.
