## Передача конфигурации жюри

По [инструкции шифрования](https://docs.ostrovok.tech/s/b9e6ec5e-5ad6-4091-9c85-a48eee9b21cc/doc/shifrovanie-sekretov-klyuchej-6Qhc4gJOPZ)
создан `secrets.env.age` в корне репозитория. Использован публичный ключ
организаторов и бинарный формат age 1.3.2, без ASCII armor. Содержимое — точная
копия текущего рабочего `.env`, по указанию владельца проекта. Отдельный
LLM-ключ для жюри не выпускался.

Рабочий `.env` остался неизменным; он в UTF-8 без BOM, не отслеживается Git и
отсутствует в доступной истории. В `.env.example` перечислены все передаваемые
имена и дополнительные необязательные настройки, все значения пустые. Провайдер,
модель и команда расшифровки указаны в README.

Проверены бинарный заголовок, единственный получатель X25519, отсутствие открытых
секретов в сдаваемых текстовых файлах и сохранность рабочего `.env`. Установка age
проверена побайтовым шифрованием/расшифровкой с временным тестовым ключом; тестовые
файлы удалены. Расшифровать сам сдаваемый файл могут только организаторы со своим
закрытым ключом. При любом изменении `.env` файл нужно зашифровать и отправить заново.

## Выполненные проверки

Проверка запуска выполнена в отдельной копии исходников, с новой PostgreSQL и
синтетическими LLM-настройками. Использовались те же Dockerfile и Compose;
чтобы не занимать порты работающего приложения, тестовые публикации — `18080`
для UI и `55433` для БД. `.env` рабочего проекта и его volume не изменялись,
Telegram в тестовом окружении отключён.

Сборка без кеша слоёв заняла **197,69 секунды (3 минуты 18 секунд)**.
Базовые образы уже были локально; время их первоначальной загрузки в замер
не входит и зависит от сети. Это измерение конкретного окружения, не гарантия
времени на любом ноутбуке. Повторный старт после `docker compose down`
с сохранённым volume занял **25,47 секунды**, все сервисы стали `healthy`.

Результаты: обычный backend-прогон — **272 теста, OK, 12 пропусков**;
с тестовой PostgreSQL — **272 теста, OK, 3 пропуска** (Linux-терминал на macOS).
Frontend — **18 unit-тестов и 21 браузерный сценарий**, все прошли;
production build и `pip check` успешны.

- Сборка обоих образов без кеша Docker, установка зависимостей из lock-файлов.
- Автоматическое создание таблиц, готовность всех трёх сервисов.
- Главная страница и статические ресурсы, `/health`, `/api/config`, OpenAPI.
- Регистрация, вход, выход, создание и история поездки; чужой аккаунт получает `404`.
- Сохранение аккаунта, сессии и поездки после `docker compose down` и повторного запуска с сохранённым volume.
- Swagger и ReDoc в Chromium; политики CSP пропускают их ресурсы только на
  страницах документации, основной интерфейс сохраняет прежние ограничения.
- Backend unittest, включая отдельный PostgreSQL-режим с mock LLM/HTTP/MCP;
  frontend unit- и браузерные тесты, production build, `pip check`.
- Markdown: проверены локальные ссылки, заголовки и `git diff --check`.

Платные LLM/API-поиски не запускались. Эта проверка подтверждает установку,
хранение и интерфейсы, но не наличие живых предложений у поставщиков.
Исторические live-прогоны содержат частичные и неуспешные сценарии:
[архив результатов](archive/live-e2e/README.md). Они не выдаются за приёмку текущей версии.

## Финальная сдача

1. Записать короткий скринкаст: регистрация → запрос поездки → результаты и
   объяснение → изменение плана → PDF и имитация оформления. Если источник
   недоступен, показать фактический частичный результат; реальные покупки не нужны.
2. Опубликовать видео, проверить просмотр без авторизации и добавить ссылку
   в начало README. Закоммитить и отправить изменение в `main`.
3. Проверить чистый запуск по README с действующими LLM-настройками. Такой
   пользовательский поиск расходует квоты и выполняется с согласованным бюджетом.
4. На окончательном коммите основной ветки в дедлайн выполнить из корня:

```bash
git switch main
git pull --ff-only origin main
git status --short
git log -1 --oneline
git tag submission
git push origin main
git push origin submission
```

Перед тегом рабочее дерево должно быть чистым, а последний коммит — содержать
финальную версию и ссылку на видео. Если тег уже существует, сначала проверьте
его через `git show submission`; существующий тег не перезаписывайте.
