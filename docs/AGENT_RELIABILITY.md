# Изолированные роли и повторная проверка

Текущий поток данных и проверки после удаления нормализаторов: [адаптивный агент](ADAPTIVE_AGENT.md). Live-измерения в конце этого документа относятся к предыдущей версии.

## Устройство

```text
travel_agent/
  agents/
    supervisor/agent.py
    transport/agent.py
    transport/tools.py
    stays/agent.py
    stays/tools.py
    experience/agent.py
    experience/tools.py
    model.py
    react.py
  prompts/
    loader.py
    supervisor.md
    transport.md
    stays.md
    experience.md
  graph.py
  tools.py
```

`graph.py` содержит отдельные узлы `supervisor`, `transport`, `stays`, `experience`, `engine`, `finish`. У каждой роли собственный ChatOpenAI, а у каждой делегации — отдельный стандартный LangChain agent, сообщения, evidence и разрешённые IDs. Это изоляция доступа и состояния внутри одного процесса; отдельные сервисы или собственный framework не создавались. `react.py` содержит общий запуск SDK и проверку результата, без базовых классов и фабрик агентов.

Конкретные инструменты объявлены в каталогах специалистов. Центральный `tools.py` отвечает за общие сетевые проверки, сохранение полных ответов и Tavily. При сборке сверяется точный allowlist; права повторно проверяются перед сетью. Ключи других ролей и LLM-токен не передаются в tool-контекст. Supervisor не получает внешних tools. Experience получает только проверенные данные проживания, без чужой ReAct-истории.

`prompts/loader.py` проверяет имя по allowlist, читает UTF-8, отклоняет пустой файл и кэширует четыре промпта. Промпты переписаны по отдельным разделам: роль, вход, алгоритм решения, ограничения, выход и остановка. Все системные тексты по-прежнему находятся в одной директории prompts. Wheel проверен на наличие новых пакетов и чтение промптов вне репозитория.

## Изменения поведения

- Все разрешённые поиски и резервные источники выбирает специалист; скрытого первичного поиска нет. Карточки с ценами проверяются по ссылкам на наблюдённые поля.
- `ToolStrategy(SpecialistSelection)` возвращает структурированный выбор внутри стандартного агента. Отдельный второй LLM-прогон для сериализации удалён. Source IDs проверяются по реально полученному evidence.
- Ограничения пользователя применяются один раз в начале хода; последующая делегация не может случайно вернуть старые даты или изменить гостей.
- Для временных MCP network_error/timeout доступны две попытки по 30 секунд с общим deadline 63 секунды. 401/403, schema_error и rate_limited не повторяются, включая ошибки внутри ExceptionGroup.
- При пустом/ошибочном 2GIS Experience может выбрать Geoapify. Другого подтверждённого источника гостиничных тарифов у Stay нет.
- При уточнении отеля полные прежние ответы доступны Stay для сравнения дат, гостей и условий. Выбор свежего отеля запускает пересборку Experience. Перед имитацией покупки Python проверяет актуальность котировок, состав гостей и совместимость дат.
- Явный запрос повторного поиска использует `refresh`; обновление Stay инвалидирует и зависимую программу, но сохраняет транспорт.
- API различает `ready`, `partial`, `unavailable`, `needs_input`, `unsupported`, `error`. Общий deadline возвращает HTTP 504 с предложением прочитать checkpoint перед повтором. Неполная поездка не выдаётся за полный подбор.

## Автоматическая проверка

Текущая offline-проверка включает исходные исследовательские тесты, сквозной workflow и сценарии адаптивности. PostgreSQL- и Linux-режимы запускаются отдельно. Команда: `.venv/bin/python -m unittest discover -s tests -v`.

Дополнительные проверки:

- loader: кэш, UTF-8, запрет обхода пути, пустой файл;
- разные узлы и фактические модули инструментов;
- модель Stay пытается вызвать search_flights — до транспортной сети запрос не доходит;
- параллельные делегации не смешивают evidence, гостей, revision и ключи;
- немедленное завершение модели не запускает скрытый поиск;
- после timeout 2GIS модель может выбрать Geoapify; оба ответа сохраняются;
- временные ошибки повторяются ограниченно, nested 403 не повторяется;
- десять повторов ошибочного workflow завершаются без зацикливания;
- drift ограничений внутри хода запрещён;
- просроченная котировка не переиспользуется при замене отеля;
- FastAPI → настоящий StateGraph → настоящие create_agent → mock MCP: уточнение, план, отель, бюджет, вопрос, даты, гости, выбор и идемпотентная simulation;
- PostgreSQL восстанавливает checkpoint и профиль после закрытия и повторного открытия клиентов.

Полная цена по-прежнему неизвестна. География и расписание посещений имеют ограничения из [инструкции](TRAVEL_AGENT.md). Доступность внешнего поставщика не гарантируется локальными тестами.

## Повторные live-сценарии

Выполнены семь отдельных диалогов на текущем endpoint в четырёх запусках скрипта во время исправлений. [Машинный отчёт](../reports/agent_reliability.json) сохраняет все результаты, включая неудачные.

Последние **два из двух** диалогов прошли проверку полного плана, названия выбранного отеля, сохранения транспорта и обновления всех трёх ролей на новые даты:

1. Запрос без дат → уточнение без внешнего поиска.
2. 12–16 ноября, двое взрослых → три варианта с реальными транспортом и проживанием.
3. Mirror Residence → один соответствующий вариант; запускался только Experience. Совместимые свежие котировки отеля и транспорта сохранены.
4. 13–17 ноября → Transport, Stay, Experience выполнены заново; новый полный вариант и даты подтверждены по состоянию и evidence.

Скрипт теперь проверяет не только отсутствие повторного транспорта, но и наличие именно запрошенного отеля. В промежуточном запуске эта проверка отсутствовала; при составлении отчёта она пересчитана по сохранённым результатам и обнаружила неполную замену из-за Tutu timeout. Этот случай не объявляется успехом.

В ранних прогонах были неполные планы из-за Tutu timeout. После ограниченных повторов и переиспользования свежих котировок последние два прогона завершились полностью. Некоторые результаты Experience и Transport содержат partial-предупреждения от дополнительных источников или лимитов; проверенные кандидаты при этом сохранены. Это подтверждает обработку ошибок и прохождение выбранных сценариев, но не гарантирует постоянную доступность Tutu, 2GIS и остальных провайдеров.

LLM расход этой доработки по `usage.cost`: **$0.0623238656**. Вместе с консервативным резервом предыдущего этапа — **до $0.7370395964**, внутри ранее разрешённого $1. Tavily live по-прежнему не проверен без ключа. Реальные покупки и платежи не выполнялись.
