# Проверка пользовательского диалога — 26.10.2026

Запуск: `python chat.py`. Подробности и команды: [инструкция](TRAVEL_AGENT.md). Отчёт: [user_dialogue_validation.json](../reports/user_dialogue_validation.json).

## Изменения

- До поиска требуется цель или явно заданные интересы. Цель сохраняется; её изменение инвалидирует Stay и Experience, сохраняя свежий транспорт.
- До пяти разных отелей: приоритет выбора Stay Agent с учётом цели, затем известная стоимость. Все наблюдённые котировки сохраняются для последующих изменений. При недостаточной выдаче вариантов меньше пяти.
- Supervisor объясняет варианты через структурированный UserResponse. Python подставляет цены, даты и предупреждения. Неизвестные расходы не превращаются в ноль. При ошибке объяснения возвращаются фактические карточки.
- Вопросы об отеле или районе запускают ограниченный веб-режим соответствующего специалиста с Tavily Search/Extract. Эти вопросы не меняют ограничения, котировки, выбор и revision. Supervisor не получает внешние tools.
- Ответы, варианты, программа по дням и выбранный вариант доступны в контексте следующего сообщения. Уточнение неоднозначного вопроса не удаляет варианты.
- `chat.py` использует тот же FastAPI/LangGraph через ASGITransport, показывает только пользовательский текст, сохраняет checkpoint в SQLite. Общий профиль интересов локально не сохраняется; серверный режим с PostgreSQL сохраняет и профиль.

## Проверки

` .venv/bin/python -m unittest discover -s tests -v `: 56 успешных тестов, один отдельный PostgreSQL-тест пропущен без тестовой БД. Новые проверки проходят через настоящий StateGraph/create_agent с mock LLM/HTTP: уточнение цели без сети, продолжение, пять различных отелей, приоритет выбора специалиста, Search + Extract с сохранением evidence, отсутствие чужого MCP, обработка missing_key, запрет выдуманных URL/ID, неизменность поездки при вопросе, сохранение списка при уточнении, восстановление SQLite и изоляция владельца, пользовательский вывод CLI без JSON. Существующие E2E изменения дат/отеля и mock booking также проходят.

Без платных запросов проверен запуск `python chat.py` с `/quit`. `uv pip check --python .venv/bin/python`, Ruff F-check и `git diff --check` проходят.

Реальный read-only прогон использовал существующий LLM endpoint, Tutu и источники Experience: сначала уточнение цели без делегации, затем пять вариантов с транспортом и проживанием; вопрос о разнице стоимости без нового поиска; вопрос о бассейне направлен в research без изменения вариантов. Experience завершился частично по лимиту. Ключ Tavily отсутствовал, поэтому корректно сообщено об отсутствии веб-источников. Реальный Search/Extract не проверен — только HTTP-fixtures.

В первом live-прогоне пояснения не прошли проверку и сработал фактический fallback. После уточнения контракта источников и увеличения лимита вывода презентации до 4096 токенов отдельная проверка финального presenter на той же реальной выдаче успешно вернула пять пояснений. После этого полный live workflow повторно не запускался; финальная сборка проверена offline. Точный источник первоначального отказа по сохранённому отчёту не установлен. Позднейшие форматирование дат/денег и приоритет выбранных Stay кандидатов проверены offline.

Новые наблюдённые расходы LLM: $0.017041222. Для прерванного вызова Experience консервативно учитывается весь лимит первого live-прогона $0.20, а не только reported usage. Вместе с предыдущей работой консервативная сумма сессии — $0.9417640764, в пределах разрешённого $1. Реальных покупок и бронирований не было.

## Ограничения

Список ограничен выдачей источников; знания об удобствах и расстояниях без веб-источников отсутствуют. Описание LLM не является подтверждением бронирования. Таймауты поставщиков и частичные результаты возможны; поиск пока последовательный и может занимать минуты. Один локальный чат на одну поездку одновременно; SQLite-режим предназначен для пользовательского теста, серверная постоянная память — PostgreSQL.
